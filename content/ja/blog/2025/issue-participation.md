OpenTelemetry にはプロジェクト開始以来、23,000人を超えるコントリビューター（GitHub 上でイシュー、コミット、プルリクエスト、コメントを共有した個人）がいることをご存知ですか？
私たちは常に皆さんの参加を推奨しています。
（多くの！）[CNCF Slack](https://slack.cncf.io/) チャンネルに参加するのも、[公開ミーティング](https://github.com/open-telemetry/community/?tab=readme-ov-file#calendar)に参加してさまざまな視点を共有するのも歓迎です。
このオープンさは私たちの最大の強みの一つですが、同時に GitHub、Slack、StackOverflow、ミーティング、さらにはソーシャルメディアへの投稿など、さまざまなルートからフィードバックが大量に寄せられることも意味します。

プロジェクトに積極的に関わり、日々エンドユーザーと仕事をしている立場として、私はコントリビューションの両面を見ています。
ユーザーはバグの修正や機能の開発を期待して GitHub イシューを作成し、メンテナーは限られた時間をどこに費やすのが最善かを見極めようと、通知の山をふるいにかけています。
規模感をお伝えすると、2024年だけでプロジェクト全体でクローズされた GitHub イシューの数は7,000件を超えました！

このように活発なプロジェクトにおいて、常に最大の課題の一つは、OpenTelemetry のユーザーやコントリビューターが何を最も重要と考えているかを理解することでした。
GitHub イシューに関して言えば、「+1」や「me too!」というコメントの連続は、この課題を解決しやすくするものではありません。
その気持ちは貴重ですが、その方法は多くのノイズを生み出し、メンテナーが実際にどれだけの人がイシューの影響を _受けている_ かを把握することを難しくしています。

私たちはこれを誰にとってもより簡単にしたいと考えています。
そこで、End-User SIG の活動の一環として、GitHub の活用方法に小さいながらも重要な変更を加える取り組みを進めてきました。
**関心を表明するための主要な手段として、👍 の[イシューリアクション](https://github.blog/news-insights/product-news/add-reactions-to-pull-requests-issues-and-comments/)の利用を推進する**というものです。

## 優先順位付けを支援するより明確なシグナル {#a-better-signal-to-help-prioritize}

ここでの目標はシンプルです。
コミュニティが何を最も重要と考えているかを伝えるための、明確で手間のかからないデータ駆動型の方法を提供することです。
メンテナーにとって、このシステムは通知のノイズを削減します。
[リアクション数でイシューをソート](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/filtering-and-searching-issues-and-pull-requests#sorting-issues-and-pull-requests)することで、コミュニティが求めているものを一目で素早く把握できます。
これにより、SIG やメンテナーがバックログの優先順位付けにおいて、より十分な情報に基づいた意思決定を行えるようになります。

エンドユーザーであるあなたにとっては、あなたのフィードバックがより見えやすくなることを意味します。
長いスレッドの中で「+1」コメントが埋もれてしまうかわりに、あなたの 👍 がイシューにより大きな重みを与える定量化可能なデータとなります。

この変更を定着させるために、いくつかの施策を展開しました。
OpenTelemetry のメンテナー向けに、リアクションの管理と解釈の方法に関する[推奨事項](https://github.com/open-telemetry/community/blob/706839937eb5886bb07da6bd9d63245839e3cc2f/guides/maintainer/popular-issues.md?from_branch=main)を公開し、ウェブサイトには[エンドユーザーにとっての意味](/community/end-user/issue-participation/)を説明するセクションを新設しました。
また、すべての OTel リポジトリの[イシューテンプレート](https://github.com/open-telemetry/community/blob/706839937eb5886bb07da6bd9d63245839e3cc2f/guides/maintainer/popular-issues.md?from_branch=main#recommended-footnote-on-issue-templates)に追加された新しい脚注として、親切なリマインダーが表示されます。
新しいイシューを作成する際には、他の人がこのアドバイスに直接アクセスできるよう、そのフッターをそのまま残してください。

## インパクトを生み出すためのクイックガイド {#your-quick-guide-to-making-an-impact}

では、これは実際にあなたにとって何を意味するのでしょうか？
簡単です。

次にイシューを閲覧するとき、読んでそのまま立ち去らないでください。
あなたも直面している問題や、実装されてほしい機能が記載されたイシューを見つけたら、**イシューの説明に 👍 リアクションを付けるだけ**です。
それだけです。
「いいね」して「チャンネル登録」するのと同じです。
それがシグナルです。

もちろん、新しい独自のユースケースや、まだ言及されていない技術的な詳細、またはメンテナーが問題を解決するのに役立つ情報をお持ちであれば、ぜひコメントを残してください。
そのような文脈は非常に貴重です！
ただし、リアクション数が多いことは強いシグナルですが、それだけでイシューが自動的に最優先になることを保証するものではないことを覚えておいてください。

オープンソースはチームスポーツであり、これは小さな行動が集まって大きなインパクトを生み出せることの好例です。

OpenTelemetry をともにより良くする取り組みにご協力いただき、ありがとうございます。
