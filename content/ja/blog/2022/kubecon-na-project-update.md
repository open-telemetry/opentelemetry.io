2022年は OpenTelemetry にとって素晴らしい1年でした。
メトリクスがファーストクラスのシグナルタイプとなり、OpenTelemetry の既存の分散トレースサポートとともに本番サービスやインフラストラクチャで使用され、重要なパフォーマンスデータをあらゆるオブザーバビリティバックエンドに送信して処理できるようになりました。
私たちが目を向けるあらゆるところで、OpenTelemetry が最大規模から最小規模まで、最先端の組織から歴史的に慎重な組織まで、あらゆる場所でテスト、展開、あるいはすでに使用されているのを目にしています。

1月以降、私たちは以下を提供しました。

- メトリクス：仕様での定義と、Java、JS、.NET、Python の SDK および計装での提供。
  Collector とプロトコルを通じたエンドツーエンドのサポートも含みます。
  さらに多くの言語実装が進行中です。
- すべての言語に対するさらなる計装。
- [優れたデモアプリケーション](../announcing-opentelemetry-demo-release)。
  サポートされているすべての言語で書かれたサービスが含まれ、すでに OpenTelemetry で計装されています。
  これは、学んだり実験したりできる OpenTelemetry の実践的な例を見るのに最適な方法であり、デモはさまざまなオブザーバビリティ分析システムを試すためにも使用できます。
- C++、Erlang、およびその他の多くの新しい言語でのトレースの安定化。
- Ruby、Erlang、Swift、.NET の自動計装の進捗。
- OpenTelemetry の3番目のシグナルタイプであるログに関する大きな進展。
- ドキュメント！
- すべてのコンポーネントに対するさまざまな改善。

コミュニティも引き続き大幅に成長しています。
[現在、GitHub 上で150以上の異なる組織から800人超の月間アクティブ開発者がいます](https://opentelemetry.devstats.cncf.io/d/7/companies-contributing-in-repository-groups?orgId=1&from=now-4y&to=now)。
これらのコントリビューターのうち、エンドユーザーの割合がますます増えています。
[上位25の貢献組織のうち10がエンドユーザー組織です](https://opentelemetry.devstats.cncf.io/d/5/companies-table?orgId=1)。
これはプロジェクトにとって非常に健全なシグナルです。
人々や企業が OpenTelemetry から多大な有用性を得ており、コントリビューションを通じてさらに皆にとって有用なものにしています。

この投稿は KubeCon の期間中に公開しています。
多くのコミュニティメンバーやエンドユーザーが集まり、OpenTelemetry とその使われ方、改善の方法、そして今後の方向性について議論しています。
今年5月の KubeCon EU では、[より正式な OpenTelemetry ロードマップを作成するプロセスを開始しました](https://docs.google.com/document/d/1jt47KPwgDG_-4kR4J5GtFSCEhQO3CHgUdAwpCKTQHO8/edit#)。
デトロイトでもそのプロセスを継続する予定です。
この投稿はカンファレンスに先立って書いているため、完全な結果をお伝えすることはできませんが、最も重要と思われる項目のいくつかを紹介します。

- ログの完成：完全な仕様の策定と、各言語にわたるその仕様の実装。
- OpenTelemetry をより使いやすくすること。
  技術的な面（OpenTelemetry コントロールプレーンなどの新機能）と、ドキュメントの整備やユーザーフィードバックの収集などの両方を含みます。
- クライアント計装：ウェブ、モバイル、デスクトップのクライアントアプリケーションからパフォーマンスデータを取得するための OpenTelemetry の拡張。
  これにより、真のユーザー向け SLO からデータを取得したり、トレースでエンドツーエンドのレイテンシーを表示したりすることが可能になります。
- プロファイリング：サービスのパフォーマンス（現在メトリクスとトレースで取得されているもの）を、コード内の実際の関数パフォーマンスに結びつけます。
- コントリビューターおよびメンテナーのエクスペリエンスの改善。

今年の残りと来年に向けた私たちの重点は、すべての言語、シナリオ、インテグレーションにわたる OpenTelemetry の既存機能の充実と、上記のロードマップ項目の両方にあります。
上述のとおり、今後数週間のうちにこれらを盛り込んだより正式なロードマップドキュメントを公開する予定ですが、それぞれの優先順位や進捗は、各項目に関わるコミュニティメンバーの数と投じられる労力に依存するという点を留意することが重要です。

ログ、クライアント計装、プロファイリングなど、これらの多くはすでに進行中です。
私たちがこれらの新しい取り組みに期待しているのは、プロジェクトの有用性を拡大し、当初のビジョンにより近づけるだけでなく、コミュニティに新しいメンバーの波を呼び込み、その知識、経験、そして情熱を OpenTelemetry に加えてくれているからです。
プロジェクトにとって刺激的な日々であり、急速に成長し採用されていく様子を見ることは、関わるすべての人にとって活力となっています。
