サイトは Docsy のスクリプトに加え、独自のスクリプトをいくつか追加しています。
これらは `assets/js/` 配下にあり、`script.html` パーシャルを通じて読み込まれます。
Hugo の `js.Build` が各ファイルをバンドルし、本番ビルドではさらにミニファイとフィンガープリントを行い、サブリソース整合性ハッシュを出力します。
2種類のテンプレートがこれらを読み込みます。

- **フック**: body-end フック `layouts/_partials/hooks/body-end.html` は、すべてのページまたはゲートされたサブセットで実行されるスクリプト用です。
  head-end フックは、Kapa ウィジェットの事前初期化用です。
- **ショートコード**: レジストリ検索フォームや config-types アコーディオンなど、特定の機能がそれを使用するページで必要とするスクリプト用です。

## Body-end スクリプト {#body-end-scripts}

| スクリプト                     | ページ                                                             | 目的                                                                                                                                                   |
| ------------------------------ | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `blog-sidebar-entry-opener.js` | ブログのインデックスページとページャーページ（最初のページに作用） | サイドバーの最新2つの年グループを展開する                                                                                                              |
| `imageZoom.js`                 | すべて                                                             | コンテンツ画像のクリックズーム                                                                                                                         |
| `navScroll.js`                 | すべて                                                             | サイドバーのアクティブなエントリをビューにスクロールすることを意図しているが、アクティブ状態がこのスクリプトの実行後に適用されるため、現在は動作しない |
| `tracing.js`                   | Netlify ビルド（一時停止解除時）                                   | [ウェブサイトテレメトリー](../../features/#website-telemetry)、一時停止中                                                                              |

## ブログサイドバーエントリオープナー {#blog-sidebar-entry-opener}

`blog-sidebar-entry-opener.js` は、ページにゲートされている唯一の body-end スクリプトであり、サイドバーに作用する唯一のスクリプトです。

### ブログインデックスへのゲーティング {#gating-to-the-blog-index}

body-end フックはすべてのページでレンダリングされるため、オープナーはページの `.Path` でゲートされています。
`.Path` はすべてのロケールで同一です: `{{ if eq .Path "/blog" }}`。

`.Path` によるゲートでは、ページネーションされたリストの最初のページだけを特定することはできません。
Hugo はリストのページャーページを1つのセクションページからレンダリングするため、`.Path`、`.RelPermalink`、`.Pages` は `/blog/` と `/blog/page/2/` で同一であり、現在のスライスはページャー（`.Paginator`、または `.Paginate` が返したもの）だけが知っています。
Docsy のテンプレートがページネーションしないままにしているリストページ（空のブログなど）で `.Paginator` を呼び出すと、そのページがページネーションされ、`page/1/` エイリアスが公開されます。
そのため、オープナーはすべてのページャーページで読み込まれ、実行時に `location.pathname` で `/page/` をテストしてスキップします。

### サイドバーへの作用 {#acting-on-the-sidebar}

サイトは Docsy のキャッシュされたサイドバー（`ui.sidebar_cache_limit: 1`）を使用しています。
サイドバーのルートごとに1つのナビゲーションがあり、アクティブ状態なしで非表示（`d-none`）として配信されます。
Docsy の `chrome-nav.js` が `DOMContentLoaded` でハイドレーションします。
アクティブ状態を適用し、ナビゲーションを表示します。
ブログインデックスは、すべてのセクションのランディングページと同様に、両方の[ビルド種別](../../build/#build-kinds)でそのナビゲーションをインラインで持っているため、そこでの body-end スクリプトはパース中、表示前に実行され、サイドバーが現れる前にサイドバーの状態を設定できます。
オープナーはそのタイミングで2つの年グループを確認します。
リーンビルドでは、他のページはプレースホルダーをかわりに持っており、`chrome-nav.js` がナビゲーションをフェッチした後に埋めますが、これは body-end スクリプトには間に合いません。
JavaScript が無効の場合、サイドバーは非表示のままです。
